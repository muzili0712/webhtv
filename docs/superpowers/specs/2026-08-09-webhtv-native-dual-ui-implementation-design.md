# WebHTV 原生双端 UI 一比一实施设计

**日期：** 2026-08-09  
**状态：** 已确认，待编写实施计划  
**目标：** 将已确认的电影感聚焦设计稿一比一落地到现有 Android 工程；不以 WebView 或静态 mock 替代既有业务能力。

## 目标与边界

本次重构覆盖手机与 TV 的全部设计页面、状态页和高频 Dialog，并接入现有真实数据和操作：点播、直播、站点/线路、播放、收藏、历史、文件、音频、播放器设置、个性化、源管理、工具和维护能力。

不重写现有播放器、网络、数据源、存储或业务模型；改动集中在 Java + XML/ViewBinding 的 UI 容器、布局、样式、导航、焦点与现有状态的绑定。不得使用 WebView 承载设计稿，也不进行 Jetpack Compose 全量迁移。

## 设备与 Autosize 合约

| 场景 | 设计基准 | 原生实现 |
|---|---:|---|
| 手机普通页面 | 540 × 960 dp | `src/mobile` 竖屏布局，Autosize 以 540 × 960 为基准 |
| TV | 960 × 540 dp | `src/leanback` 横屏布局，Autosize 以 960 × 540 为基准 |
| 手机视频全屏 | 960 × 540 dp | 仅视频/直播播放器请求横屏；退出后恢复竖屏 |
| 手机音频 | 540 × 960 dp | 默认保持竖屏，支持跨页面迷你播放器 |

资源尺寸、间距和文字按上述设计基准定义；运行时仍适配不同真实分辨率。播放器横屏不得影响普通手机页与音频页的方向。

## 实施架构

### 共享设计系统

新增或整理共享的颜色、字体、间距、圆角、阴影、层级和语义化表面令牌，并为深色、浅色、跟随系统定义可切换主题。壁纸是应用级背景状态，所有主页面、Dialog 和播放器外层均使用同一壁纸/遮罩策略，保障浅色模式的文字对比度。

共用视觉组件包括：内容卡片、Hero、搜索入口、设置行、标签/Chip、空/错误状态、确认/列表/进度/嵌套 Dialog、播放器设置项。组件不持有业务数据，只接受现有 ViewModel/Fragment/设置接口提供的状态。

### 双端 UI 层

`src/mobile` 和 `src/leanback` 分别持有适合自身交互的布局与导航容器；同一业务页面可共享数据接口、Adapter 模型和事件契约，不能以同一 XML 强行适配两套布局。

手机使用底部导航、顶部搜索、BottomSheet 和竖屏详情；TV 使用左侧导航、顶部快捷入口、横向详情、右侧面板和明确的遥控器焦点图。两端都复用既有 Fragment、Dialog、播放器和数据仓库，替换其视觉壳层和必要的导航承载方式。

### 状态流与真实业务绑定

主题、壁纸、当前点播/直播源、线路及播放器设置由既有设置/存储层作为唯一事实来源。详情与播放器共享同一份字幕、弹幕、画面比例、倍速、清晰度和线路状态；设置变更即时刷新当前 OSD 和返回后的详情页。

点播源、直播源管理必须操作现有真实集合和持久化规则，包括新增、启停、默认、健康状态和策略。当前内容线路与全局源管理分别建模，不能用 UI mock 替代。

## 页面与入口映射

| 模块 | 手机入口 | TV 入口 | 既有能力 |
|---|---|---|---|
| 首页、搜索、点播 | 底部导航、顶部搜索 | 左侧导航、顶部搜索 | 站点、筛选、分类、详情 |
| 直播 | 底部导航 | 左侧导航 | 频道、分组、节目单、线路 |
| 详情、选集 | 竖屏详情 | 横向详情 | 收藏、历史、播放、选集、线路 |
| 视频播放器 | 960×540 横屏 OSD | 横屏 OSD | 播放、字幕、弹幕、画面、倍速、清晰度、线路 |
| 音频播放器 | 竖屏与迷你播放器 | TV 全屏/迷你态 | 队列、歌词、音频播放 |
| 收藏、历史、文件 | 我的内页 | 我的内页 | 真实收藏、记录、文件 |
| 设置、个性化 | 我的 → 设置与个性化 | 设置 → 个性化 | 主题、壁纸、跟随系统 |
| 点播源、直播源 | 设置 → 来源管理 | 设置 → 来源管理 | 真实增删、启停、默认、健康、策略 |
| 工具、维护 | 设置二级页/Dialog | 设置二级页/Dialog | 扫描、推送、备份、恢复、更新 |
| 扩展详情/状态 | 对应详情或 Dialog | 对应详情或 Dialog | TMDB/人物、Keep、报告、投屏、空/错/进度 |

壁纸入口固定为“手机：我的 → 设置与个性化 → 壁纸”和“TV：设置 → 个性化 → 壁纸”。点播与直播分别具有明确的主导航入口；当前线路同时从详情页和播放器 OSD 可达。

## 交互规则

返回顺序固定为：关闭顶层 Dialog/BottomSheet/OSD → 退出播放器扩展面板 → 返回页面层级 → 退出当前根页。TV 上所有可操作控件必须进入可预测的四向焦点顺序，并提供可见焦点态；手机保留触控优先的列表、底部导航、半屏设置单与播放器手势。

视频播放器支持单击显示/隐藏 OSD、双击快进/快退、长按临时 2× 倍速并在释放时还原。手机音频不进入横屏视频播放器，最小化后通过跨页迷你播放器恢复。

## 交付阶段

1. 建立主题、壁纸、Autosize 双端基准和通用视觉组件。
2. 重构主导航、首页、搜索、点播、直播及 TV 焦点系统。
3. 重构详情、选集、视频/音频播放器和共享播放器设置。
4. 重构我的、收藏、历史、文件、设置、个性化和源管理。
5. 重构工具/维护、扩展详情、全部状态页和 Dialog；完成逐页视觉回归、交互测试与 APK 构建。

每个阶段必须保持可编译和可运行，继续使用真实业务能力，不引入不可达的静态样板页。

## 验收标准

- 540×960 手机竖屏、960×540 TV、960×540 手机视频横屏逐页与设计稿对照；导航、层级、主题、壁纸、边距、圆角和焦点样式一致。
- 深色、浅色、跟随系统及所有内置壁纸下，主页面、Dialog 和播放器文字均满足可读对比度。
- 点播、直播、详情、线路、播放器设置、收藏、历史、文件、音频、源管理、个性化、工具维护和状态页均可从设计规定入口到达并操作真实数据。
- 详情与播放器的设置值一致；手机视频横屏、音频竖屏、TV 遥控器焦点和返回层级符合交互规则。
- 新增/更新的单元与 UI 测试通过；构建 `leanback/mobile × arm64-v8a/armeabi-v7a` Debug APK 成功。
